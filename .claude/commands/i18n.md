---
description: Extract new gettext strings, then translate every new and fuzzy entry to pt-BR by hand
---

Every user-facing string in this project is Portuguese via gettext, and
`test/estoque_os_web/gettext_test.exs` fails the build on an untranslated or
fuzzy entry. This is the loop that satisfies it. Run it after **any** change
that adds or edits a `gettext(...)` call, before running the suite.

## Why this is a command and not just `mix gettext.extract --merge`

The merge does not leave new entries blank — it **guesses**, matching each new
msgid against a similar existing one, writing that translation in, and marking
the entry `fuzzy`. But `fuzzy` is a note to a human, not a gate: the wrong text
renders to the operator anyway.

Real guesses this repo has caught: `Import data` → *"Importar"*, `recorded` →
*"Registrar"*, `Conference` → *"Conferência encerrada"*, `not started` → *"não
informado"*, `to count` → *"não contada"*. Every one of them was wrong, and
every one of them would have shipped.

So: **read every fuzzy entry and rewrite it. Never just clear the flag.**

## Steps

1. Extract and merge:

   ```
   mix gettext.extract --merge
   ```

2. List what needs a human — untranslated first, then the merge's guesses:

   ```
   awk '/^msgid "/{id=$0} /^msgstr ""$/{if (id != "msgid \"\"") print id}' priv/gettext/pt_BR/LC_MESSAGES/default.po
   grep -n "fuzzy" -A 3 priv/gettext/pt_BR/LC_MESSAGES/default.po | grep msgid
   ```

3. Translate each one into Brazilian Portuguese as the warehouse would say it —
   this is read by someone holding a box, not by a translator. Match the register
   of the strings already in the file. Then drop the `, fuzzy` from the flags
   line of every entry you rewrote.

4. Confirm both lists are empty, and run the gate:

   ```
   mix test test/estoque_os_web/gettext_test.exs
   ```

## Notes

- `priv/gettext/default.pot` is generated. Never hand-edit it.
- Only `pt_BR` exists today. If a locale is added, step 3 repeats per locale.
- A msgid is English (the code is English; only the rendering is Portuguese).
  If you find yourself writing a Portuguese msgid, the `gettext(...)` call is
  wrong, not the translation.
